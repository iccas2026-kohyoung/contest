1 Problem Overview
AOI (Automatic Optical Inspection) is equipment that automatically inspects electronic components on a PCB. A camera head moves across the PCB, capturing images and performing 3D reconstruction and inspection.

📷 AOI Camera Structure

The AOI equipment has a single imaging head with a Top camera (top-down view) and multiple Side cameras (angled views) mounted together.

Top Camera

Captures the top surface of components vertically. Inspects presence, position error, orientation, etc. All components require Top imaging, and side=1 components additionally require Side imaging.

Side Camera

Captures the side solder fillet at an angle. Only applies to components with side=1. In this contest, the Side FOV is assumed to be half the size of the Top FOV.

💡 Both cameras are mounted on the same head, move together, and capture simultaneously at each position. There is no need to create separate FOVs for Side imaging only.
⚠ FOVs containing side=1 components have increased capture time of max(capture_time, side_capture_time).

🔍 What are Components and FOVs?

Components are electronic parts (resistors, ICs, etc.) mounted on a PCB, and FOV (Field of View) is the rectangular area captured in a single camera shot.

The camera moves from FOV to FOV, capturing multiple components in each shot. FOV size is fixed; participants determine the position and number of FOVs.

💡 The more components packed into each FOV, the fewer total FOVs needed, reducing both movement count and CT.

🧩 Three Problems to Solve

For the camera to efficiently traverse the PCB, three decisions must be made. Because each decision affects the others, combinatorial explosion (NP-hard) occurs, and these three decisions determine the Cycle Time (CT).

📊 CT Difference Based on FOV Layout and Inspection Order

Even with the same component layout, the total Cycle Time varies significantly depending on how FOVs are grouped and the inspection order.

🧩 PCB Component Types

Fiducial (type=2)

The origin (starting point) of the PCB coordinate system. Since slight positional errors occur when the PCB is placed on the machine, Fiducial coordinates are measured first to calibrate the entire coordinate system.

Key: Must be placed in the first FOV exclusively / No other components allowed in Fiducial FOV

Barcode (type=1)

PCB model identifier. Barcodes identify which PCB model is being inspected, allowing model-specific inspection programs to be applied. Inspected after Fiducials.

Key: Inspected after Fiducials / Multiple allowed in the same FOV / 0~4 per PCB

Normal Component (type=0)

The actual inspection targets — SMD components (resistors, capacitors, ICs, etc.). Their position, orientation, and solder quality are inspected in 3D.

Key: Inspected after Fiducial/Barcode / Order can be freely optimized

🔧 Side Camera & FOV Two-Layer Structure

Some components (side=1) require a Side camera (side solder inspection) in addition to the Top camera. The Side FOV is half the size of the Top FOV, sharing the same center point.

  • side=0 → Top camera only (most components) — OK if within Top FOV
  • side=1 → Top + Side camera required — must be fully within the smaller Side FOV

3 Constraint Details
These are mandatory conditions to ensure valid inspection results. All conditions must be satisfied without violations for a solution to be accepted.

3-1. FOV Size — Physical size of the area captured in a single camera shot

#ConstraintDetails
1.1Top FOV Size The Top camera's field of view. Defined by the fov_size value in input_size.csv.
FOV size is defined separately for the x and y axes.
Example (input_size.csv)
fov_size x=50mm, y=50mm → Top FOV is a 50mm × 50mm rectangle
1.2Side FOV Size In this contest, the Side camera's field of view is assumed to be half of the Top FOV (per axis).
side_fov_w = fov_width / 2.0, side_fov_h = fov_height / 2.0
The Side FOV and Top FOV share the same center point.
Example
If Top FOV is 50×50mm → Side FOV is 25×25mm, same center point
1.3Top + Side Combined Capture The AOI equipment has a Top Camera (shoots downward from above) and Side Cameras (shoot at oblique angles for side views). The Top camera inspects the component surface, while the Side cameras inspect solder fillet geometry on the component sides. Both cameras are mounted on the same capture head and move together simultaneously.

Components with side=1 require additional Side camera capture on top of the Top capture. Since both cameras capture simultaneously at the same position, the imaging time is the longer of the two.
The Top FOV and Side FOV share the same center point — a single FOV position captures both Top and Side simultaneously. No need for separate Side-only FOVs.
However, if an FOV contains even one side=1 component, its capture time becomes max(capture_time, side_capture_time).
💡 Optimization Tip: When side=1 and side=0 components are in the same FOV, the Side capture cost (side_capture_time) is incurred only once while normal components are also inspected — saving FOVs. If Side components fit within the Side FOV and normal components within the Top FOV, one FOV covers everything.
💡 Key Point: FOV size is fixed as input. What participants decide is the position (x, y) and number of FOVs.
⚠ Side FOV Warning: side=1 components must be fully contained within the blue Side FOV area. Even if inside the Top FOV, being outside the Side FOV is a constraint violation.
💡 Optimization Tip: Side components benefit from being clustered near the FOV center. Since the Side FOV is half the Top, Side components far from center may require separate FOVs, increasing FOV count.

3-2. Component Placement — Rules for placing components within FOVs

#ConstraintDetails
2.1Full Component Coverage All components must be included in at least one FOV. Missing components constitute a constraint violation.
Verification (checker.py)
Check that comp_mask[idx] is 1 for each component. If any is 0, it fails.
2.2Fully Contained Within FOV All 4 corners (tl, tr, bl, br) of a component must be inside the FOV area.
Any part of a component extending outside the FOV is a constraint violation.
Criteria
fov_tl_x ≤ comp_tl_x AND fov_tl_y ≤ comp_tl_y AND fov_br_x ≥ comp_br_x AND fov_br_y ≥ comp_br_y
2.3Fiducial FOV Restriction Fiducial components (type=2) must be placed in the first FOV exclusively. No other components allowed in the Fiducial FOV.
Fiducials define the origin (starting point) of the PCB coordinate system for precise position calibration.
2.4Barcode FOV Rules Barcodes (type=1), unlike Fiducials, can have multiple in the same FOV.
Barcodes are PCB model identifiers used to determine which PCB model is being inspected. Must be inspected after Fiducials.

A Barcode FOV can also contain Normal components (type=0). The FOV's type is determined by the highest type among its components: fov.type = max(component types in FOV). So a FOV containing both Barcode(1) and Normal(0) components becomes a Barcode FOV (type=1).
Fiducial vs Barcode
Fiducial (type=2): First FOV, exclusive — no other components allowed
Barcode (type=1): Multiple per FOV, can include Normal(0) components too → Group nearby Barcodes and Normals for efficient placement
💡 Optimization Point: Grouping Barcodes with nearby Normal components into one FOV reduces total FOV count. The FOV is automatically classified as type=1 (Barcode) and placed in the correct inspection order.
2.5Large Component Split Inspection When a component is larger than its effective FOV, it is inspected by splitting across multiple FOVs.
The union of split FOVs must fully cover the entire component area without gaps.
Effective FOV per component type
side=0: effective FOV = Top FOV (fov_width × fov_height)
side=1: effective FOV = Side FOV (fov_width/2 × fov_height/2)
A side component exceeding the Side FOV (but smaller than the Top FOV) is still a “large component” and must be split.
Verification
The is_target_fully_covered() function verifies that the union of effective FOV areas fully covers the component. For side=1 large components, the coverage check uses the Side FOV area of each assigned FOV. Grid-based partitioning checks for any uncovered cells.
2.6Side Component Placement Components with side=1 must have all 4 corners fully contained within the Side FOV (1/2 of Top) area.
Since the Side FOV is smaller than the Top FOV, a component may fit in the Top FOV but not the Side FOV.
Criteria (checker.py code)
side_tl_x = fov.x - fov_width/4, side_br_x = fov.x + fov_width/4
side_tl_y = fov.y - fov_height/4, side_br_y = fov.y + fov_height/4
All 4 corners of the Side component must be within this area to pass.
2.7Step Mixing Prohibited All components within a single FOV must have the same step (height) value.
Mixing step=0 and step=1 components in the same FOV is a constraint violation.
Verification (checker.py code)
steps = set(component.iloc[idx]['step'] for idx in comp_idx)
if len(steps) > 1: ERROR — Collect step values of components in the FOV into a set; if more than 1, violation.
❌ Violation: 3 components with step=0 + 1 component with step=1 in one FOV → Disqualified
Valid: 4 components all with step=0 in one FOV → Pass
💡 Optimization Tip: The basic strategy is to pack as many components as possible into each FOV to minimize total FOV count. Fewer FOVs mean fewer moves and less 3D Reconstruction/Capture overhead. However, components at different step heights cannot share the same FOV, so they must be grouped by step.

Before / After — FOV Placement Optimization

❌ Before — Inefficient placement (9 FOVs)
✅ After — Optimized placement (4 FOVs)
Comparison
Before: 9 FOVs, 8 moves → 9 Captures + 9 3D Reconstructions + high travel overhead
After : 4 FOVs, 3 moves → 4 Captures + 4 3D Reconstructions + minimal travel overhead

3-3. FOV Inspection Order — Rules requiring certain component-type FOVs to be inspected first

#ConstraintDetails
3.1FOV Type-based order The FOV type is determined by the maximum type value among its components. The inspection order is:
Fiducial FOV (type=2) → Barcode FOV (type=1) → Normal FOV (type=0)

In other words, type values must be in descending order (higher types first).
Verification (checker.py)
all(fov.type[i] ≥ fov.type[i+1] for i in range(len-1))
In the row order of output_fov.csv, each FOV's type must be greater than or equal to the next.
3.2Fiducial FOV Ordering When there are multiple Fiducial FOVs, the FOV containing the lower-indexed Fiducial in input_component.csv must be inspected first.
Example
If Fiducial components are at index=0 and index=5, then the FOV containing index=0 must come before the FOV containing index=5.
Order 1
Fiducial FOV
type=2 (PCB reference point)
❯
Order 2
Barcode FOV
type=1 (PCB model identifier)
Multiple per FOV allowed
❯
Order 3
Normal FOV
type=0 (order freely optimizable)
💡 Optimization Point: Fiducial/Barcode FOV order is fixed, but Normal FOV (type=0) ordering is freely optimizable. This is the TSP (path optimization) problem.
💡 Optimization Tip: Applying local search methods like 2-opt or Or-opt can significantly reduce travel distance compared to simple Nearest Neighbor. However, since switching between FOVs at different step heights incurs a +5s penalty, visiting same-step FOVs consecutively before switching steps takes priority over distance optimization.

3-4. Inspection Resources & CT Calculation — How the Core pipeline determines Cycle Time

#ConstraintDetails
4.1Core Roles Core 0: Camera X/Y movement + FOV Capture (always sequential)
Core 1~2: Dedicated 3D Reconstruction (assigned to idle core after Capture)
Core 3+: Component Inspection (assigned to least-busy core after 3D Reconstruction)
Core 0 sequence (per FOV)
[Move from prev FOV → next FOV] → [Capture] → [Move to next FOV] → ...
Core 0 continuously cycles: Move→Capture→Move→Capture without pause.
4.2Core Count (Fixed Input) max_core is a fixed input constraint per dataset (random 4–16). The Checker uses this value directly — participants cannot change or optimize this value.
Cores 0 through (max_core-1) are used.
Example
max_core=8 → Core 0 (Move+Capture), Core 1~2 (3D Reconstruction), Core 3~7 (5 Inspection cores)
max_core=16 → Core 3~15 all used for Inspection → more parallel Inspection → lower CT
4.3Capture Time Time required to capture (acquire image) each FOV. Uses the capture_time value from input_parameter.csv.
4.43D Reconstruction Time Time to generate 3D data from the captured image. Uses the recon_time value.
4.5Component Inspection Time Each component's inspection time is defined individually in the time field of input_component.csv.
Components within an FOV are sequentially assigned to the least-busy Inspection Core.
4.6Side Capture Time If an FOV contains even one side=1 component, both Top and Side cameras capture simultaneously, so the capture time is the longer of the two.
FOV with Side comps: imaging_time = max(capture_time, side_capture_time)
FOV without Side comps: imaging_time = capture_time
4.7Z-axis Step Transition Delay When two consecutive FOVs have different step (height) values, the camera must adjust its Z-axis height, incurring an additional 5.0-second delay.
The Z-axis movement itself is fast, but settling time is needed for camera vibration to stabilize after the move. Capture quality requires waiting until vibration has fully dampened.
This delay is added on Core 0 after movement, before Capture.
Same step: Core 0 = [Move] → [Capture]
Different step: Core 0 = [Move] → [+5.0s Z transition] → [Capture]
🔥 5 seconds is a very large penalty. Compared to typical travel time of 0.1~0.5s, it is 10~50x larger. The key strategy is to place same-step FOVs consecutively to minimize the number of transitions.

Core Pipeline Timeline (Example: max_core=5, 5 FOVs)

Camera Movement
FOV Capture
3D Reconstruction
Component Inspection
Z-axis Step Transition (+5s)
💡 CT = max(completion time of last task across all Cores). Since this is a pipeline, multiple FOVs are processed concurrently. FOV2's Capture and FOV1's 3D Reconstruction run in parallel.
💡 Optimization Tip: If components with large inspection times (time) are concentrated in one FOV, it creates a bottleneck on specific Cores. Distributing high-time components across multiple FOVs improves load balance across Cores and reduces CT. Also, since fewer cores (8) means fewer Inspection Cores, it is important to find placements that perform well across all core counts.

3-5. Camera Movement — X/Y-axis Trapezoidal Velocity Profile

#ConstraintDetails
5.1Independent X, Y Control X and Y axes move independently and simultaneously. Each axis follows a Trapezoidal velocity profile.
Parameters (input_parameter.csv)
v_x, v_y: 200–1000 mm/s (max velocity, random per dataset)
a_x, a_y: 4900–9800 mm/s² (acceleration, random per dataset)
5.2Travel Time Calculation Calculate X and Y travel times separately; the longer one is the actual travel time.
travel_time = max(T_x, T_y)
Numerical Example (v=1000, a=9800)
Moving from FOV center (100, 50) → (200, 80):
X distance=100mm, Y distance=30mm
Threshold th = v²/a = 1000²/9800 ≈ 102mm
X (100mm < 102mm): T_x = 2√(100/9800) ≈ 0.202s
Y (30mm < 102mm): T_y = 2√(30/9800) ≈ 0.111s
travel_time = max(0.202, 0.111) = 0.202s

Camera Movement Diagram

Trapezoidal Velocity Profile Formulas

Variables
  d = distance along one axis (|Δx| or |Δy|)
  v = max velocity for that axis (v_x or v_y)
  a = acceleration for that axis (a_x or a_y)

Threshold distance th = v² / a

Long distance (d ≥ th):
  T = 2v/a + (d − th) / v
  → Accel → Constant velocity → Decel (trapezoid)

Short distance (d < th):
  T = 2√(d/a)
  → Accel → Decel (no constant velocity, triangle)

Final Travel time = max(Tx, Ty)
  X, Y axes move simultaneously; the slower axis determines travel time
💡 Optimization Tip: Since travel time is max(T_x, T_y), having a long distance on one axis and short on the other incurs little penalty. For example, moving 200mm on X and 10mm on Y means Y movement is essentially free. When ordering FOVs, a sweep pattern along one axis then stepping to the next row is fundamentally efficient.
4 Step (Height) Region Details
The PCB is a stepped board with regions at different Z-axis heights. This section explains step-related constraints in detail.

📍 What is a Step Region?

Specific rectangular regions on the PCB have different heights. Defined in input_step_region.csv.

  • If a component is inside a step region → step=1
  • If outside the step region → step=0
  • 1~2 step regions exist

🚫 Step Constraint Summary

Step Mixing ProhibitedCannot place step=0 and step=1 components in the same FOV
Step Transition DelayIf consecutive FOVs have different steps: +5.0s extra (camera vibration settling time after Z-axis move)
Optimization StrategyVisit all step=0 FOVs first → then all step=1 FOVs (only 1 transition)

1 문제 개요
AOI(Automatic Optical Inspection)는 PCB 위의 전자 부품을 자동 검사하는 장비입니다. 카메라 헤드가 PCB 위를 이동하며 부품을 촬영하고, 3D 복원 및 검사를 수행합니다.

📷 AOI 카메라 구조

AOI 장비에는 하나의 촬상 헤드에 Top 카메라(위→아래)와 여러 대의 Side 카메라(비스듬한 각도)가 함께 탑재되어 있습니다.

Top 카메라

부품의 상면을 수직으로 촬영합니다. 부품 유무, 위치 오차, 방향 등을 검사합니다. 모든 부품이 Top 촬영 대상이며, Side 부품 (side=1)은 Side 촬영도 추가로 수행합니다.

Side 카메라

부품의 측면 납땜 필렛을 비스듬히 촬영합니다. Side 부품 (side=1)만 해당되며, 본 대회에서는 촬상 영역(Side FOV)을 Top의 절반 크기로 가정합니다.

💡 두 카메라는 같은 헤드에 탑재되어 동시에 이동하고, 한 위치에서 동시 촬영합니다. 별도로 Side만을 위한 FOV를 만들 필요가 없습니다.
⚠ Side 부품 (side=1)이 포함된 FOV는 촬상 시간이 max(capture_time, side_capture_time)으로 증가합니다.

🔍 부품과 FOV란?

부품(Component)은 PCB 위에 실장된 전자 부품(저항, IC 등)이며, FOV(Field of View)는 카메라가 한 번에 촬영하는 직사각형 영역입니다.

카메라는 FOV 단위로 이동하며, 한 FOV 안에 여러 부품을 담아 한 번에 촬영합니다. FOV 크기는 고정이고, 참가자는 FOV의 위치와 개수를 결정합니다.

💡 FOV 하나에 부품을 많이 담을수록 전체 FOV 수가 줄고, 이동 횟수도 줄어 CT가 감소합니다.

🧩 풀어야 하는 3가지 문제

이 카메라가 PCB 위를 효율적으로 돌아가며 촬영하려면 3가지 결정이 필요합니다. 각 결정이 서로 영향을 주기 때문에 조합 폭발(NP-hard)이 발생하며, 이 세 가지 결정이 Cycle Time(CT)을 결정합니다.

📊 FOV 구성과 검사 순서에 따른 CT 차이

동일한 부품 배치에서도 FOV를 어떻게 묶고, 어떤 순서로 검사하느냐에 따라 전체 Cycle Time이 크게 달라집니다.

🧩 PCB 부품 유형 (type)

Fiducial (type=2)

PCB 좌표계의 시작점(원점)을 정의하는 기준점입니다. PCB가 장비에 놓일 때 미세한 위치 오차가 발생하므로, Fiducial 좌표를 먼저 측정하여 전체 좌표계를 보정합니다.

특징: 반드시 첫 번째 FOV에 단독 배치 / Fiducial FOV에는 다른 부품 포함 불가

Barcode (type=1)

PCB 모델 구분자입니다. 바코드를 통해 어떤 PCB 모델인지 식별하며, 모델별 검사 프로그램을 적용하기 위해 Fiducial 다음으로 먼저 검사합니다.

특징: Fiducial 다음으로 검사 / 동일 FOV에 여러 개 가능 / PCB당 0~4개

일반 부품 (type=0)

실제 검사 대상인 SMD 부품(저항, 콘덴서, IC 등)입니다. 부품의 위치·방향·납땜 상태 등을 3D로 검사합니다.

특징: Fiducial/Barcode 이후 검사 / 순서 자유 최적화 가능

🔧 Side 카메라와 FOV 두 겹 구조

3 제약 조건 상세
검사 결과의 유효성을 보장하기 위한 필수 조건입니다. 모든 조건을 위반 없이 만족해야 유효한 솔루션으로 인정됩니다.

3-1. FOV 크기 — 카메라가 한 번에 촬영하는 영역의 물리적 크기

#제약 조건상세 설명
1.1Top FOV 크기 Top 카메라의 촬상 영역. input_size.csv의 fov_size 값으로 주어집니다.
x축과 y축 각각의 FOV 크기가 별도로 정의됩니다.
예시 (input_size.csv)
fov_size x=50mm, y=50mm → Top FOV는 가로 50mm × 세로 50mm 직사각형
1.2Side FOV 크기 본 대회에서는 Side 카메라의 촬상 영역을 Top FOV의 절반으로 가정합니다 (각 축 기준).
side_fov_w = fov_width / 2.0, side_fov_h = fov_height / 2.0
Side FOV와 Top FOV는 중심점을 공유합니다.
예시
Top FOV가 50×50mm이면 → Side FOV는 25×25mm, 중심점 동일
1.3Top + Side 통합 촬상 AOI 장비에는 Top 카메라(위에서 아래로 촬영)와 Side 카메라(비스듬한 각도에서 측면을 촬영)가 장착되어 있습니다. Top 카메라는 부품의 상면을 검사하고, Side 카메라는 부품 옆면의 납땜 필렛(solder fillet) 형상을 검사합니다. 두 카메라는 같은 촬상 헤드에 함께 탑재되어 동시에 이동합니다.

Side 부품 (side=1)은 Top 촬상에 더해 Side 카메라 촬상도 필요합니다. 두 카메라가 같은 위치에서 동시에 촬영하므로, 촬상 시간은 둘 중 긴 쪽이 됩니다.
Top FOV와 Side FOV는 같은 중심점을 공유하며, 한 번의 FOV 위치 이동으로 Top과 Side를 동시에 촬상합니다. 별도로 Side만을 위한 FOV를 만들 필요가 없습니다.
단, FOV에 Side 부품 (side=1)이 1개라도 포함되면 해당 FOV의 촬상 시간은 max(capture_time, side_capture_time)이 됩니다.
💡 최적화 팁: Side 부품 (side=1)과 일반 (side=0) 부품이 같은 FOV에 함께 들어오면, Side 촬상 비용(side_capture_time)은 어차피 1회만 발생하면서 일반 부품도 함께 검사할 수 있어 FOV 수 절약이 됩니다. Side 부품이 Side FOV 안에 있고, 일반 부품이 Top FOV 안에 있으면 하나의 FOV로 모두 커버 가능합니다.
💡 핵심: FOV 크기는 입력으로 고정되어 있습니다. 참가자가 결정하는 것은 FOV의 위치(x,y)와 개수입니다.
⚠ Side FOV 주의: Side 부품 (side=1)은 파란색 Side FOV 영역 안에 완전히 포함되어야 합니다. Top FOV 안에 있더라도 Side FOV 밖이면 제약 위반입니다.
💡 최적화 팁: Side 부품은 FOV 중심 근처에 모여 있을수록 유리합니다. Side FOV가 Top의 절반이므로, FOV 중심에서 먼 Side 부품은 별도 FOV가 필요해져 FOV 수가 증가합니다.

3-2. 부품 배치 — FOV 안에 부품을 배치하는 규칙

#제약 조건상세 설명
2.1전체 부품 커버 모든 부품은 최소 1개의 FOV에 포함되어야 합니다. 누락된 부품이 있으면 제약 위반입니다.
검증 방법 (checker.py)
각 부품에 대해 comp_mask[idx]가 1인지 확인. 하나라도 0이면 실패.
2.2FOV 영역 내 완전 포함 부품의 4개 꼭짓점(tl, tr, bl, br)이 모두 FOV 영역 안에 있어야 합니다.
부품의 일부라도 FOV 밖으로 나가면 제약 위반입니다.
판정 조건
fov_tl_x ≤ comp_tl_x AND fov_tl_y ≤ comp_tl_y AND fov_br_x ≥ comp_br_x AND fov_br_y ≥ comp_br_y
2.3Fiducial FOV 제한 Fiducial 부품(type=2)은 반드시 첫 번째 FOV에 단독 배치됩니다. Fiducial FOV에는 다른 부품 포함 불가.
Fiducial은 PCB 좌표계의 시작점(원점)으로, 정밀한 위치 보정에 사용됩니다.
2.4Barcode FOV 규칙 Barcode(type=1)는 Fiducial과 달리 여러 개가 동일한 FOV에 포함될 수 있습니다.
Barcode는 PCB 모델 구분자로, 어떤 PCB 모델인지 식별하기 위해 Fiducial 다음으로 먼저 검사합니다.

Barcode FOV에는 일반 부품(type=0)도 함께 포함될 수 있습니다. FOV의 타입은 포함된 부품 중 가장 높은 type으로 결정됩니다: fov.type = max(FOV 내 부품 type). 따라서 Barcode(1)와 일반(0) 부품이 같은 FOV에 있으면 해당 FOV는 Barcode FOV(type=1)가 됩니다.
Fiducial vs Barcode
Fiducial(type=2): 첫 번째 FOV에 단독 배치, 다른 부품 불가
Barcode(type=1): 동일 FOV에 여러 개 가능, 일반 부품(type=0)도 함께 포함 가능 → 가까운 Barcode와 일반 부품을 묶어서 효율적 배치
💡 최적화 포인트: Barcode 근처의 일반 부품을 같은 FOV에 묶으면 총 FOV 수가 줄어듭니다. FOV는 자동으로 type=1(Barcode)로 분류되어 올바른 검사 순서에 배치됩니다.
2.5큰 부품 분할 검사 부품 크기가 해당 부품의 유효 FOV보다 큰 경우, 여러 FOV로 분할하여 검사합니다.
분할된 FOV들의 합집합이 부품 전체 영역을 빈 틈 없이 커버해야 합니다.
부품 유형별 유효 FOV
side=0: 유효 FOV = Top FOV (fov_width × fov_height)
side=1: 유효 FOV = Side FOV (fov_width/2 × fov_height/2)
Side 부품이 Side FOV보다 크지만 Top FOV보다 작은 경우에도 “큰 부품”으로 분류되어 분할 검사 대상입니다.
검증 방법
is_target_fully_covered() 함수로 유효 FOV 영역들의 합집합이 부품을 완전 커버하는지 확인합니다. side=1 큰 부품은 각 FOV의 Side FOV 영역을 기준으로 커버 여부를 판정합니다. 격자 분할 방식으로 빈 셀이 없는지 검증.
2.6Side 부품 배치 Side 부품 (side=1)은 Side FOV(Top의 1/2) 영역 안에 4개 꼭짓점이 모두 포함되어야 합니다.
Side FOV는 Top FOV보다 작으므로, Top FOV에는 들어가지만 Side FOV에는 안 들어가는 경우가 발생할 수 있습니다.
판정 조건 (checker.py 코드)
side_tl_x = fov.x - fov_width/4, side_br_x = fov.x + fov_width/4
side_tl_y = fov.y - fov_height/4, side_br_y = fov.y + fov_height/4
이 영역 안에 Side 부품의 4 꼭짓점이 모두 있어야 통과.
2.7단차 혼합 금지 하나의 FOV 안에 있는 모든 부품은 같은 단차(높이) 값을 가져야 합니다.
높이=0인 부품과 높이=1인 부품을 같은 FOV에 섞으면 제약 위반입니다.
검증 방법 (checker.py 코드)
steps = set(component.iloc[idx]['step'] for idx in comp_idx)
if len(steps) > 1: ERROR — FOV 내 부품들의 단차 값을 set으로 모은 뒤, 2개 이상이면 위반.
❌ 위반 예: FOV 안에 높이=0 부품 3개 + 높이=1 부품 1개 → 실격
정상 예: FOV 안에 높이=0 부품만 4개 → 통과
💡 최적화 팁: FOV 하나에 최대한 많은 부품을 넣어 전체 FOV 수를 줄이는 것이 기본 전략입니다. FOV 수가 줄면 이동 횟수도 줄고, 복원/촬상 오버헤드도 감소합니다. 단, 단차가 다른 부품은 같은 FOV에 넣을 수 없으므로 단차별로 분리하여 그룹핑해야 합니다.

❌ Before — 비효율 배치 (FOV 9개)

3-3. FOV 검사 순서 — 특정 부품이 포함된 FOV를 먼저 검사해야 하는 규칙

#제약 조건상세 설명
3.1FOV 타입별 순서 FOV에 포함된 부품의 최대 type 값으로 FOV type이 결정됩니다. 검사 순서는:
Fiducial FOV (type=2) → Barcode FOV (type=1) → 일반 FOV (type=0)

즉, type 값이 내림차순이어야 합니다 (높은 type이 먼저).
검증 (checker.py)
all(fov.type[i] ≥ fov.type[i+1] for i in range(len-1))
output_fov.csv의 행 순서에서, 앞쪽 FOV의 type이 뒤쪽보다 크거나 같아야 합니다.
3.2Fiducial FOV 간 순서 Fiducial FOV가 여러 개일 때, input_component.csv에서 인덱스가 작은 Fiducial이 속한 FOV를 먼저 검사합니다.
예시
Fiducial 부품이 index=0과 index=5에 있다면 → index=0의 FOV가 반드시 index=5의 FOV보다 앞에 와야 합니다.
순서 1
Fiducial FOV
type=2 (PCB 기준점)
❯
순서 2
Barcode FOV
type=1 (PCB 모델 구분자)
동일 FOV에 여러 개 가능
❯
순서 3
일반 FOV
type=0 (자유 순서 최적화 가능)
💡 최적화 포인트: Fiducial/Barcode FOV의 순서는 고정되지만, 일반 FOV(type=0) 간의 순서는 자유롭게 최적화할 수 있습니다. 이 부분이 TSP(경로 최적화) 문제입니다.
💡 최적화 팁: 단순 최근접 이웃(Nearest Neighbor)보다 2-opt, Or-opt 등 국소 탐색을 적용하면 이동 거리를 크게 줄일 수 있습니다. 단, 단차가 다른 FOV 간 전환 시 +5초 페널티가 발생하므로, 같은 단차 FOV를 연속 방문한 뒤 단차를 전환하는 것이 거리 최적화보다 우선입니다.

3-4. 검사 리소스 & CT 계산 — Core 파이프라인으로 Cycle Time이 결정되는 방식

#제약 조건상세 설명
4.1Core 역할 Core 0: 카메라 X/Y 이동 + FOV 촬상 (항상 순차 실행)
Core 1~2: 3D 복원 전담 (촬상 완료 후, 둘 중 빈 Core에 할당)
Core 3 이상: 부품별 검사 (복원 완료 후, 가장 빈 Core에 할당)
Core 0의 순서 (매 FOV마다)
[이전 FOV 위치 → 다음 FOV 위치 이동] → [촬상] → [다음 FOV 이동] → ...
즉, Core 0은 쉬지 않고 이동→촬상→이동→촬상을 반복합니다.
4.2Core 수 (고정 입력) max_core는 데이터셋별 고정 입력 (랜덤 4–16). Checker가 이 값을 그대로 사용. 참가자가 변경/최적화 불가.
Core 0 ~ Core (max_core-1)까지 사용.
예시
max_core=8이면 → Core 0(이동+촬상), Core 1~2(복원), Core 3~7(검사 5개)
max_core=16이면 → Core 3~15가 모두 검사에 활용 → 병렬 검사 증가 → CT 감소
4.3촬상 시간 각 FOV의 촬상(이미지 획득)에 소요되는 시간. input_parameter.csv의 capture_time 값.
4.43D 복원 시간 촬상된 이미지로부터 3D 데이터를 생성하는 시간. recon_time 값.
4.5부품 검사 시간 각 부품별 검사 시간은 input_component.csv의 time 필드에 개별 정의됩니다.
FOV 안의 부품들이 순서대로 가장 빈 검사 Core에 할당됩니다.
4.6Side 촬상 시간 FOV에 Side 부품 (side=1)이 1개라도 포함되면, Top과 Side 카메라가 동시 촬영하므로 촬상 시간은 둘 중 긴 쪽이 됩니다.
Side 부품 포함 FOV: imaging_time = max(capture_time, side_capture_time)
Side 부품 미포함 FOV: imaging_time = capture_time
4.7Z축 단차 전환 지연 연속된 두 FOV의 단차(높이) 값이 다르면 카메라의 Z축 높이를 전환해야 하며, 5.0초의 추가 지연이 발생합니다.
Z축 이동 자체는 빠르지만, 이동 후 카메라 진동(흔들림)이 안정될 때까지의 settling time이 필요하기 때문입니다. 촬상 품질을 보장하려면 진동이 완전히 소멸된 뒤 촬영해야 합니다.
이 지연은 Core 0에서 이동 후, 촬상 전에 추가됩니다.
같은 단차: Core 0 = [이동] → [촬상]
다른 단차: Core 0 = [이동] → [+5.0초 Z전환] → [촬상]
🔥 5초는 매우 큰 페널티입니다. 이동 시간이 보통 0.1~0.5초인 것에 비해 10~50배 큽니다. 같은 단차의 FOV를 연속 배치하여 전환 횟수를 최소화하는 것이 핵심 전략입니다.

Core 파이프라인 타임라인 (예시: max_core=5, FOV 5개)

카메라 이동
FOV 촬상
3D 복원
부품 검사
Z축 단차 전환 (+5s)
💡 CT = max(모든 Core의 마지막 작업 완료 시간). 파이프라인이므로 여러 FOV가 동시 처리됩니다. FOV2의 촬상과 FOV1의 복원이 동시에 진행됩니다.
💡 최적화 팁: 검사 시간(time)이 큰 부품들이 한 FOV에 몰리면 특정 Core에 병목이 생깁니다. 검사 시간이 큰 부품을 여러 FOV에 고르게 분산하면 Core 간 부하 균형이 좋아져 CT가 줄어듭니다. 또한 Core 수가 적을수록(8) 검사 Core가 부족하므로, 모든 Core 수에서 고르게 좋은 배치를 찾는 것이 중요합니다.

3-5. 카메라 이동 — X/Y축 사다리꼴 속도 프로파일

#제약 조건상세 설명
5.1X, Y축 독립 제어 X축과 Y축은 독립적으로 동시에 이동합니다. 각 축은 사다리꼴(Trapezoidal) 속도 프로파일을 따릅니다.
파라미터 (input_parameter.csv)
v_x, v_y: 200~1000 mm/s (최대 속도, 데이터셋별 랜덤)
a_x, a_y: 4900~9800 mm/s² (가속도, 데이터셋별 랜덤)
5.2이동 시간 산정 X축, Y축 이동 시간을 각각 계산한 후, 더 오래 걸리는 쪽이 실제 이동 시간입니다.
이동시간 = max(T_x, T_y)
수치 예시 (v=1000, a=9800 기준)
FOV 중심 (100, 50) → (200, 80)으로 이동 시:
X축 거리=100mm, Y축 거리=30mm
임계거리 th = v²/a = 1000²/9800 ≈ 102mm
X축(100mm < 102mm): T_x = 2√(100/9800) ≈ 0.202초
Y축(30mm < 102mm): T_y = 2√(30/9800) ≈ 0.111초
이동시간 = max(0.202, 0.111) = 0.202초

카메라 이동 개념도

사다리꼴 속도 프로파일 공식

변수 정의
  d = 한 축의 이동 거리 (|Δx| 또는 |Δy|)
  v = 해당 축의 최대 속도 (v_x 또는 v_y)
  a = 해당 축의 가속도 (a_x 또는 a_y)

임계거리 th = v² / a

긴 거리 (d ≥ th):
  T = 2v/a + (d − th) / v
  → 가속 → 등속 → 감속 (사다리꼴)

짧은 거리 (d < th):
  T = 2√(d/a)
  → 가속 → 감속 (등속 구간 없음, 삼각형)

최종 이동 시간 = max(Tx, Ty)
  X, Y축은 동시에 이동하며, 더 느린 축이 이동 시간을 결정
💡 최적화 팁: 이동 시간은 max(T_x, T_y)이므로, 한 축의 이동 거리만 길고 다른 축은 짧은 경우 손해가 적습니다. 예를 들어 X축으로 200mm 이동하면서 Y축으로 10mm 이동하면, Y축은 사실상 공짜입니다. FOV 순서를 정할 때 한 축 방향으로 쭉 훑다가(sweep) 다음 줄로 넘어가는 패턴이 기본적으로 효율적입니다.
4 단차(높이) 영역 상세
PCB는 단차 보드로, Z축 높이가 다른 영역이 존재합니다. 이 섹션에서 단차 관련 제약을 상세히 설명합니다.

📍 단차 영역이란?

PCB 위의 특정 직사각형 영역이 다른 높이를 가집니다. input_step_region.csv에 정의됩니다.

  • 부품이 단차 영역 안에 있으면 → 높이=1
  • 단차 영역 밖에 있으면 → 높이=0
  • 단차 영역은 1~2개 존재

🚫 단차 관련 제약 요약

단차 혼합 금지하나의 FOV 안에 높이=0과 높이=1 부품 동시 배치 불가
단차 전환 지연연속 FOV의 단차가 다르면 +5.0초 추가 (Z축 이동 후 카메라 진동 settling time)
최적화 전략높이=0 FOV들을 먼저 모두 순회 → 높이=1 FOV들 순회 (전환 1회)
